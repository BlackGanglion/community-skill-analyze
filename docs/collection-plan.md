# 社区 Skill 采集与更新方案

状态：方案待确认，尚未开始采集。

## 目标

先从 [LobeHub](https://lobehub.com/skills) 获取 Skill 目录，将 **Skill 元信息和对应源码仓库的全部文件** 保存到 egg-server，供后续分析，并持续更新。首期覆盖 LobeHub，之后再扩展其他社区来源。

## 保存什么

- **每条 Skill 一份元信息**：名称、描述、作者、分类、来源链接、许可证、仓库地址、仓库内路径、commit SHA、采集时间和状态。
- **每个仓库一份完整版本快照**：包含源码、文档、测试、配置、隐藏文件、LFS 文件和子模块，不裁剪成单个 Skill 目录。同仓库同 commit 只保存一次，多个 Skill 共用。
- 来源指定分支或版本时按其获取，否则使用默认分支。保存该 commit 的完整文件树，暂不回溯全部 Git 历史。
- 无源码、访问失败或文件不完整的条目保留元信息及原因，不算下载成功。记录许可证状态，非开源或许可待确认内容单列。

## 存在哪里

数据目录：`/home/egg/data/community-skill-analyze/`。

```text
skills/<skill_id>/metadata.json          # Skill 元信息与仓库关联
repositories/<repo_id>/<commit>/files/  # 完整仓库文件
repositories/<repo_id>/<commit>/manifest.json
catalog.sqlite                         # 检索索引与采集进度
reports/                               # 采集结果与失败清单
```

建议使用 Python + SQLite。数据独立于代码仓库保存，不上传到本项目 GitHub；下载内容只作为资料，不安装或执行。

## 怎么拉取

1. 验证 LobeHub 官方接口的认证和完整分页能力，获取目录元信息。
2. 解析每条 Skill 对应的仓库和路径，按仓库去重下载，固定 commit。
3. 核验整仓文件清单、LFS 和子模块，建立 Skill 与仓库的关联。
4. 支持限速、失败重试和断点续传；输出条目数、完整仓库数、失败原因及磁盘占用。

目录无法完整枚举时明确标注覆盖缺口，不以热门榜代替全量，也不将 LobeHub 收录等同于整个开源社区。

## 怎么更新

- **每天**检查目录新增与修改，按仓库检查源码版本；变化后保存新快照，保留旧版本。
- **每周**全目录对账，并滚动复核所有仓库，补漏和重试；不只依赖市场更新时间。
- 使用服务器定时任务，避免重复运行；容量不足时暂停并报告，不能自动裁剪仓库。定期备份元信息、索引和快照。

## 实施顺序

先取约 **100 条代表性 Skill** 验证整条链路，测量整仓大小和下载速度；确认磁盘与访问额度足够后，执行首次全量，再启用定时更新。第一阶段只完成采集，后续再做分类、去重分析和质量评估。

验收标准：元信息可查询、完整仓库可离线浏览、来源版本可追溯、失败有清单、中断可恢复、重复运行不重复下载。
